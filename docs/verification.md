## 测试边界

UI 自动化直接向指定应用投递输入，不经过全局事件 tap。因此 AX 输入验证使用只在临时数据目录中启用的 30 秒活动标记；它验证真实控件 → AX 通知 → 增量计数 → SQLite 的完整路径。真实 Fn 按键和麦克风听写没有在这次自动化中实际录音验证；Fn 时序由状态机测试覆盖，系统 tap 能否创建由已安装签名应用实际验证。

旧版高 CPU 峰值没有在短时间空闲观察中重现，所以不声称“降低了百分之多少”。修复移除了源码中明确的 0.3 秒全量文本轮询、2 秒持续图表重建及无界 AX 调用，并对新版本做了空闲采样和长文本逻辑压力检查。不同第三方编辑器、输入法预编辑和语音流式修正仍受它们暴露的 AX 信息限制。

所有 UI 假数据、受控输入和 Portman 写操作使用独立临时目录。没有为了测试修改用户已有转发、SSH 配置、系统安全设置或正式统计数据。

原始测试输出保存在本机 `output/verification/`，不随仓库发布：`selfcheck.txt`、`native-input-check.json`、`portman-ui-roundtrip.json`、`installed-diagnostics.json`、`history-preservation.json`、`idle-cpu-summary.json`。

## 0.2.4 Python 兼容性

首次 GitHub macOS 15 / Python 3.14 检查暴露后台启动超时。本机 Python 3.14 进一步复现：仍有活动 TCP 连接时，停止映射会等待客户端关闭，而客户端清理又被放在服务器关闭之后。Python 3.12+ 的 `Server.wait_closed()` 等待活动连接释放，因此修正为先停止接收新连接、清理客户端流，再等待服务器完全关闭。

本地管理 HTTP 服务仅绑定数字 loopback 地址，启动时移除了无必要的反向 DNS 查询，并增加解析器不可用时仍可启动的回归检查。Python 3.9.6 和 3.14.2 各自运行完整的 15 项测试均通过，包含真实 SSH 双向转发与连接清理。

语义依据：[Python asyncio Server.wait_closed](https://docs.python.org/3/library/asyncio-eventloop.html#asyncio.Server.wait_closed)。
